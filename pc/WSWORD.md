# WSword PC on Savage Wind Recomp

This folder is **Savage Wind Recomp 0.4.1-alpha.4** (https://github.com/Revivedx/SavageWindRecomp, MIT, by Revivedx
and the Savage Wind contributors, built on Peiikai's LAS Recomp), imported unchanged in its own commit. It is the
base of WSword's PC build from 0.3.0-pc.1. `LICENSE` is Savage Wind's and ships in the zip as `LICENSE.txt`.

## WSword's changes

**Names.** The release's files are WSword's:
- `WSword.exe`, its import library `WSword.dll.a` (the game code library links against it), and `WSword Configuration.exe`;
- `WSword.log` and `WSword.prev.log`, and the settings file `WSword.ini`;
- the zip `WSword-<version>-windows.zip`, with a top folder `WSword/`;
- WSword's icon (`docs/icon/wsword.ico`, `wsword_1024.png`).

The name shown in the windows, menus, messages and translations is WSword. Comments still say Savage Wind's in a few places.

The `SAVAGEWIND_*` environment variables, `swgame.dll`, `swgen/` and the Linux and macOS names are Savage Wind's.

**Version.** The version is `SAVAGEWIND_VERSION` in `runtime/ui/launcher.mm`: `0.3.18-pc.1`. `SW_BASE_VERSION` is the Savage Wind release it is built on, shown after the version on the configuration screen. The log's first line names both.

**An older WSword's folder** (`runtime/paths.c` `wsword_older_root`):
- **What it is.** 0.2.8-pc.x kept each game version in a folder of its own (`v182`, `v190`, with `game_version.txt` naming the one in use), on LAS Recomp's layout.
- **When.** Unzipped over such a folder, where the exe's folder has no `extracted/exefs` of its own.
- **What happens.** That version's folder becomes the data folder, with its game files (`extracted/exefs`, `extracted/romfs`) and `save/`. Savage Wind's `remove_old_image` then removes the old `romfs.bin`.

**The game code built at once** (`runtime/ui/launcher.mm`):
- **When.** The game files are set up, but the game code is missing or was built for another version (an older WSword's folder, or an update).
- **What happens.** The build starts by itself, as Set up game files does with no folder chosen.

**The Glass Slate look** (0.3.1-pc.1, from WSword 0.2.8):
- `runtime/ui/launcher.mm` `glass_main`: the start screen - a glass panel (the icon, the versions, PLAY, Saves, Settings, Game files, Quit, the game files' state and the GPU), chips (refresh rate, frame generation, battery) and a card (the last save, Resume, the modes). Savage Wind's Settings and game files pages behind it, in the same look.
- `runtime/ui/menu.mm` `tabs_body`: Settings as a rail of pages (Files, Video, Audio, Controls, Language, Saves, Quit in game) with BACK, the open page under its title; `style_init`'s navy glass and cyan; Inter (OFL, `third_party/fonts/Inter`) for the menus.
- `runtime/ui/option_rows.mm`: the rows as glass tiles, the selected row's name and description in a card.
- Settings > Files (`prelaunch_tab`): Look - the background (`look/background.png` next to the exe; `runtime/ui/splash.mm` shows it, else the shipped `launcher-background.png`) and the icon (`settings.h` `app_icon`, `runtime/paths.c` `rt_window_icon`: the window's and the taskbar's) - and Lossless Scaling (the player's own `Lossless.dll`, checked by `lsfg_check_dll`, copied to `lsfg/Lossless.dll` next to the exe) - and NVIDIA DLSS (the player's own `nvngx_dlss.dll`, copied next to the exe).
- Modes (`runtime/settings.c` `settings_apply_mode`): Battery 30 fps with AMD FSR 1, Performance 60, Turbo 120, Unlocked - on the start screen's card, Video > Mode and the game's Options > Video.

**Lossless frame generation** (0.3.1-pc.1, from WSword 0.2.8): `third_party/lsfg-vk` (GPL-3.0, `README.WSword.md` there), `runtime/nvn/vulkan/lsfg.cpp` / `lsfg.h`, and in `device.c` `lsfg_prepare` and `present_locked`:
- **Settings** (`settings.h`): `lsfg` (0 off, 1-3 frames made: Video > Frame generation's Lossless 2x / 3x / 4x - AMD FSR 3 is off then), `lsfg_flow` (0 Automatic), `lsfg_perf`.
- **Each game frame:** its image copied into the backend's source image, that submission signalling the backend's timeline (`exec.c` `vk_next_submit_timeline`; `record.c` carries a second wait and a third signal); once the recorder has made it, the backend's passes go on the queue; each generated frame is drawn as the game's are (`vk_present_draw_view`: the same post passes) by a present that waits for its own value.
- **Pacing:** the frame rate counts the frames on screen (`hle/framepace.c`: the game's frame time x the presents per frame, `g_fg_active`); each group of presents is spaced evenly over the game's frame time (`present_wait_turn`'s pos / group). While groups are presented they go to the present thread on a second queue (`present_threaded`), made where it is safe (not NVIDIA before Turing, #36), so the game's thread doesn't wait; the swapchain has an image more for each further frame of a group.
- Paused in the menus, the map, the title screen and the F1 menu (the game draws at the full rate there), as FSR 3's.

**Settings over the game** (0.3.2-pc.1, from WSword 0.2.8): `runtime/ui/menu.mm` `overlay_enabled` is on (Savage Wind had it off: its settings only in the game's own Options, which still has them). F1, Back + Start or the guide button opens Settings in the Glass Slate look - Video, Audio, Controls, Language, Quit - and BACK, B or Esc closes it. `SAVAGEWIND_OVERLAY=0` turns it off. The game's Options > Video keeps Savage Wind's 19 rows (the game's screen has room for no more): WSword's Frame generation choice (Off, AMD FSR 3, Lossless 2x / 3x / 4x) takes the FSR 3 toggle's place; Mode and Lossless's own options are in the F1 Settings.

**NVIDIA DLSS** (0.3.2-pc.1): Video > Upscaler's NVIDIA DLSS (`settings.h` `UPSCALE_DLSS`, `output_scale.c` `rt_dlss`), on NVIDIA RTX GPUs with the player's own `nvngx_dlss.dll`.
- **The bridge:** NVIDIA's NGX library is MSVC's, which this MinGW build can't link, so `tools/dlss_bridge/wsword_dlss.cpp` is built with MSVC into `wsword_dlss.dll` (by `build-windows.yml`, against NVIDIA's DLSS SDK from https://github.com/NVIDIA/DLSS) with a plain C interface (`runtime/nvn/vulkan/dlss_bridge.h`). `runtime/nvn/vulkan/dlss.c` loads it.
- **The device** (`device.c`): on an RTX GPU, the instance and device extensions NGX names are enabled (with buffer device address), if the driver has all of them.
- **Each frame** (`exec.c` `dlss_scene`, where FSR 3's upscale is): the scene at the render size, its depth (`fsr3_depth.frag`) and motion vectors (`dlss_mv.frag`, RG16F), FSR 3's jitter (in at least 8 phases) and motion-vector scale, into a storage image at the output size; Sharpening's CAS after it. Anti-aliasing (SMAA, TAA) is off with it, as with FSR 3. A second composite of the same scene in a frame reuses the first's output.
- **On the recorder thread** (0.3.3-pc.1): NGX records into the frame's command buffer from a `record.c` `rec_call` packet, in order with the commands around it, so the translating thread doesn't wait for the recorder (`rec_drain`) every frame. It drains only to start NGX and when the feature is made again (other sizes, mode or model: `wsdlss_release_feature`, the device idle first). A failed frame shows the scene blitted plainly into DLSS's output.
- **The model** (0.3.3-pc.1, Video > DLSS model, `settings.h` `dlss_model`, `dlss.c` `dlss_preset`): NGX's render preset for every mode. Automatic is NVIDIA's default on RTX 40 and newer (`device.c` `renderer_gpu_rtx40`: PCI device id 0x2600 and up) and the transformer K on RTX 20 / 30, where a 310.5+ `nvngx_dlss.dll`'s defaults for Performance (M) and Ultra Performance (L) cost 2-5x K's. CNN (E), Transformer (K) and Transformer 2 (M; L for Ultra Performance) pick one.
- **Its GPU time:** a pair of timestamps around it each frame, read back 8 frames later without waiting; the average in the performance overlay, Upscaler's description and the log every 1800 frames.
- **Failures:** NGX not starting, or DLSS failing three frames in a row, turns DLSS off for the run, with the reason in Upscaler's description (`dlss_status`) and the log. `SAVAGEWIND_NO_DLSS=1` leaves the bridge alone. NGX's own messages: the first 200 in the log (all with `SAVAGEWIND_DLSS_LOG=1`).
- **`dlss_available`** runs many times a frame (with DLSS on, at every camera the game makes: `output_scale.c` `rt_jitter_on`), so the `nvngx_dlss.dll` lookup behind it is cached for half a second.

**NVIDIA DLSS frame generation** (0.3.4-pc.1): Video > Frame generation's NVIDIA DLSS 2x / 3x / 4x (`settings.h` `dlssg`), through NVIDIA's Streamline SDK in its manual hooking mode, with the player's own `nvngx_dlssg.dll` in `streamline\`.
- **The bridge** (`tools/dlss_bridge/wsword_sl.cpp`, `dlss_bridge.h` `wssl_*`, ABI 3): loads `streamline\sl.interposer.dll` at run time (its NVIDIA signature checked), `slInit` with manual hooking and frame-based tagging, DLSS-G, Reflex and PCL.
- **At startup only** (`vulkan/dlssg.c` `dlssg_start`, from `device.c` `create_instance`), when the setting is on and `nvngx_dlssg.dll` is there: the instance, the window's surface (`vkCreateWin32SurfaceKHR`), the device and the swapchain functions (create, destroy, images, acquire, present, device wait) are Streamline's. Unsupported (`wssl_device_ready`: no RTX 40, scheduling off, an old driver): the feature unloaded, a plain swapchain. Changing the setting needs a restart.
- **While it's in** (`device.c`): presents inline on the game's queue (no present thread: Streamline's own presents keep the inputs in order with it), no present ids, SDR, and VSync On / Adaptive as Fast (no VSync with it on Vulkan). Off (`wssl_off`) before the swapchain is made again.
- **Each frame:** the inputs of frame generation's own (`exec.c` `vk_fg_generate`: the HUD-less copy, the scene's depth, fg_mv.frag's camera and Link's box vectors) and its camera in Streamline's terms (row vectors; view z forward; clip z 0..1: `dlssg_camera`). `vk_dlssg_prepare` makes them into images the size of the game's rectangle in the window, placed as the present places the game's image (its flip and crop; `dlssg_depth.frag`, `dlssg_mv.frag`; the HUD-less copy post-processed and drawn as the game's image is), tagged with that rectangle as the backbuffer's subrect. Constants, tags and options go in a `rec_call` packet on the recorder thread (outside any rendering), before the present.
- **Reflex markers:** simulation end and render submit start at the present, render submit end before it, present start and end around it, then (outside the GPU lock) Reflex's sleep and the next frame's simulation start.
- **Pacing:** `g_fg_active` is the multiplier while it makes frames (framepace.c: the game draws one in that many); off in the menus (mode off, the resources kept).
- **Failures:** three `wssl_frame` failures in a row turn it off for the run. `SAVAGEWIND_NO_DLSSG=1` leaves Streamline out; `SAVAGEWIND_DLSSG_LOG=1`: Streamline's verbose log; `SAVAGEWIND_DLSSG_INPUTS_AT=<frame>`: its inputs saved as PNGs.

**Mods** (0.3.5-pc.1, from WSword 0.2.8): `runtime/mods.c` / `mods.h`, `ui/mods_tab.mm` (Settings > Mods, page id 4) and `services/fs.c`.
- `mods/<mod>/romfs/` in the data folder (the working directory), sorted by name; `settings.h` `mods_off` holds the ones turned off ('|' between names). A folder named for the DLC's title (`01007EF00011F001`) is the DLC's own; another mod's DLC files are its `romfs/aoc/0010/`.
- `fs.c` `image_roots`: when an image is indexed (`rom_index`), its overlay roots are `SAVAGEWIND_ROMFS_OVERLAY` first, then the mods' (`mods_roots`). Each root is walked once into a sorted list (`RootFile`), so `overlay_file` is a binary search, not a stat per file; the first root with a file wins, and `add_new_files` adds each root's new files once.

**ReShade** (0.3.6-pc.1): `runtime/nvn/vulkan/reshade.c` / `reshade.h`, Settings > Video > ReShade and ReShade depth (`settings.h` `reshade`, `reshade_own_depth`), Settings > Files > ReShade (`launcher.mm`), and the bridge's `tools/dlss_bridge/wsword_reshade.cpp` (`wsrs_*`, ReShade's add-on API headers in `third_party/reshade`).
- **Its DLL:** the player's own `ReShade64.dll` in `reshade\` next to `WSword.exe`: Settings > Files > ReShade copies it, or takes it out of ReShade's setup program (`reshade_import`: the setup is the program with a ZIP archive appended; checked for ReShade's exports and x64).
- **At startup** (`device.c` `create_instance`, `reshade_instance_layers`), with the setting on: ReShade's layer manifest written next to the DLL (`ReShade64.json`, as its installer's), that folder put first on the loader's layer path (`VK_ADD_LAYER_PATH`; `VK_LAYER_PATH` for an older loader, only for the instance), `RESHADE_DISABLE_LOADING_CHECK=1` (as a layer it otherwise loads only for programs its installer set up), its base path the `reshade` folder (`RESHADE_BASE_PATH_OVERRIDE`) unless a `ReShade.ini` from its installer is next to `WSword.exe`, and `VK_LAYER_reshade` enabled on the instance. A failed instance is made again without it. With it, presents stay on the game's queue and thread (`present_threaded`): its effects run in its `vkQueuePresentKHR`, in order with WSword's depth image.
- **The game's depth** (unless ReShade depth is ReShade's own detection): `ReShade.ini`'s `[ADDON] DisabledAddons` gets `Generic Depth` (taken out again for ReShade's own detection), and once ReShade is loaded the bridge registers as its add-on ("WSword game depth": only effect runtime events, which every ReShade build gives add-ons) and binds the view `wsrs_depth` gives to `DEPTH` at `reshade_begin_effects` (when it changes, or effects reload). Each present (`present_locked`, before the game's image is drawn) `exec.c` `vk_reshade_depth` fills an R32F image the window's size from frame generation's camera candidates (`fg_draw`, also with `g_rs_want`; the HUD-less copy only for frame generation): `shaders.c` `reshade_depth.frag` places the scene depth as the present places the game's image, takes each texel's distance from the projection (`B / (z + A)`) and encodes it for ReShade.fxh's defaults (reversed; far plane 1000: linear depth = metres / 1000); outside the game's rectangle, and with no 3D scene, 0. It is left in `SHADER_READ_ONLY_OPTIMAL`, the layout ReShade's descriptors name.
- `SAVAGEWIND_NO_RESHADE=1` leaves it out.

**The ray tracing report** (0.3.7-pc.1; for the ray-traced sun shadows to come): Ctrl+F9 (`hle/input.c`; F9 alone is still the whole frame's dump) reports the next frame (`device.c`: `g_rt_report`, `rt_caps_log` - the GPU's ray tracing and transform feedback extensions, also logged at startup). `exec.c` `rt_report_draw` logs (`[rtr]`) each draw into the sun's shadow cascades (depth targets of `RS_SHADOW`: shaders, topology, counts, whether the fragment shader discards, the view; its context constant buffer c3 once per buffer) and each draw that samples them (targets, textures; full-screen ones: their fragment constant buffers, and their pass's targets saved per channel in `build/rt-report/` at the pass's end). `vk_fg_generate` logs the world camera's context buffer, and `present_locked` saves the frame (`build/rt-report/frame.png`).

**Ray-traced sun shadows** (0.3.8-pc.1, experimental; `runtime/nvn/vulkan/rtshadow.c` / `rtshadow.h`, which describe it in full; Settings > Video > Ray-traced shadows, `settings.h` `rt_shadows`).
- **The device** (`device.c` `create_device`): `VK_KHR_acceleration_structure`, `VK_KHR_ray_query`, `VK_KHR_deferred_host_operations`, `VK_EXT_transform_feedback`, `VK_KHR_push_descriptor` and buffer device addresses, wherever the GPU has them all (`g_vk.rt`; `SAVAGEWIND_NO_RT=1`: never), so the setting turns on in the game.
- **The capture** (`exec.c` draw path): a triangle list into an `RS_SHADOW` depth target runs its program's `ShaderKey.xfb` variant once built (`maxwell/translate.c`: the game's clip position, before the y flip and depth remap, also to `rt_clip`, a transform feedback output), between `rts_capture_begin` / `rts_capture_end`, which bind its stretch of the capture buffer. A capture variant whose pipeline isn't built yet falls back to the plain one (`rts_repipe`). Only the sun's cascades: not a standard perspective camera in c3, the first cascade's view rotation.
- **The mask**: a full-screen draw sampling an `RS_SHADOW` texture with depth compares and writing a target's red channel notes the mask, its depth and the world camera (fragment c3, `rts_mask_seen`); at that pass's end (`vk_end_pass_at`) `rts_run` records, on the recorder thread (`rec_call`), the vertices' transform to the world (`rts_xform.comp`, each cascade's inverse view-projection), one BLAS per cascade (each run of draws a geometry; alpha-tested - the fragment shader discards - not opaque), the TLAS (instance mask: the cascade), the rays (`rts_trace.comp`: 4 over the sun's disc, against the finest cascade the pixel is in; an alpha-tested candidate blocks where the game's own map of that cascade - drawn with the cut-outs - has a surface at least as near the light there, `solid()`; foliage within 30 cm passes) and a copy of the mask; then `shaders.c` `rts_mask.frag` rewrites the mask's red channel (3x3 depth-aware filter), its other channels kept.
- 0.3.9-pc.1: triangle strips and fans are captured too ((n - 2) x 3 vertices, an upper bound: the capture buffer is refilled with NaN after each frame's rays, so what a draw leaves unwritten forms no triangle); a sun caster draw not captured (`rts_capture_missed`: its variant compiling...) keeps the game's mask as well that frame (`rts_mask.frag`: the darker of the two).
- 0.3.10-pc.1: the rays start from the scene's full-resolution depth (`exec.c` `fg_world_depth`: the world camera candidate whose view-projection the mask pass was given), not the mask pass's depth attachment, which the 0.3.9 report showed isn't the scene's depth (every ray started at the camera and met nothing).
- 0.3.11-pc.1 (not ray tracing: NVIDIA DLSS frame generation): `device.c` `pick_device` enumerates the GPUs through Streamline's `vkEnumeratePhysicalDevices` when it is loaded. Streamline's `vkCreateDevice` takes the instance from what its `vkEnumeratePhysicalDevices` noted for the GPU (`sl.interposer` `wrapper.cpp`: `s_vk.instanceDeviceMap[physicalDevice]`); WSword's own enumeration left it null, so the plugins' instance table was empty and `sl.common` called address 0 right after "Initializing plugins" - WSword closed at start, every time, since 0.3.4-pc.1 (RTX 4070 SUPER, driver 621.01, Streamline 2.14.16).
- 0.3.13-pc.1 (0.3.12-pc.1's neural rendering beta taken out again):
  - ReShade before the HUD and frame generation (`exec.c rs_pre_apply`, `reshade.c reshade_draw`, `wsword_reshade.cpp wsrs_effects`): with frame generation in play (FSR 3, Lossless, DLSS; `device.c` sets `g_rs_pre` at each present), the composited scene (`fg.out_rt`, linear 10-bit) is blitted into an 8-bit sRGB image, ReShade's effects drawn on it through the effect runtime's `render_effects` on its immediate command list, flushed on the game's queue from the recorder thread (WSword's work submitted first), with a depth image of that size (`rs_depth_into`, no flip), and blitted back before the HUD's first draw. The frame's presents then draw none: the bridge's `present` event calls `render_effects` with no target, which marks the frame's effects done (ReShade's `runtime.cpp`), until `reshade_frame_end` after the frame's last present. Before, ReShade drew at every present, generated frames too: its cost twice or more per game frame took what frame generation gave. `SAVAGEWIND_RESHADE_AT_PRESENT=1`: as before.
  - The DLC merged into the game's RomFS (`fs.c aoc_merged`, `romfs_has_dlc_merged`), none set up apart: add-on content 1 is the game's RomFS (`aoc:u` lists it, `OpenDataStorageByDataId` opens it, the title menu's button comes back). `SAVAGEWIND_NO_MERGED_DLC=1`: not.
  - NVIDIA DLSS frame generation: `dlssg-starting` in the data folder from Streamline's start until the swapchain is made through it (`dlssg_start_ok`); found at the next start, frame generation is turned off and saved, so a crash in Streamline doesn't keep WSword from starting.
- 0.3.14-pc.1, Ray-Tracing (Settings > Video, `ray_tracing`; `ray_traced_shadows` still read): the shadows' cone 0.012 -> 0.005 (about the sun's disc) and 8 rays a pixel (4 before), which the user found softer and blurrier than the game's own; ambient occlusion in the same trace (`trace_src`: 6 cosine-weighted rays of 1.5 m against the pixel's cascade's opaque geometry, foliage culled - `gl_RayFlagsCullNoOpaqueEXT` - into the rays' result's .b), put on the composited scene before the HUD (`exec.c rt_ao_apply`, `rt_ao.frag`: a 5 x 5 depth-aware filter, 85% strength). `rts_run` no longer reads its RunBlock after handing it to the recorder thread (it freed it).
- 0.3.15-pc.1, Glass Slate 2 (the UI concepts' design): the start screen (`glass_main`) a rail (Home, Saves, Settings, Mods - `GA_MODS`, Settings page 4 - Game files; the game files, GPU and driver at its foot; Quit) and a hero over the picture (the last save, PLAY, Choose a save, chips for what's on, the three newest saves from `sc_list_slots`), the modes at the top right; Settings' rail badges (RT on Video, mods on / all on Mods); Video's Ray-Tracing first, as a hero card (`opt_hero_next`: a taller row, a switch, the F6 keycap); in game, quick toggles beside the page title (`quick_toggles`: Ray-Tracing, frame generation off / its last, ReShade - "next start" once changed - and the performance overlay); the setup page's four steps and found rows when not set up. Headings in Chakra Petch Bold (OFL, `third_party/fonts/ChakraPetch`, `g_glass_head`; Inter Bold without it).
- 0.3.16-pc.1 added path tracing (a bounce of light from the composited scene, `rts_pt`); 0.3.17-pc.1 took it out again at the user's request.
- 0.3.17-pc.1, the frame rate's ceiling (Video > Frame rate Off, `framepace.c FPS_CEILING`): 1000 fps, 300 before; the game's step floor (`rt_vfr_update`) and the controllers' step floor (`framepace_presented`, 30 / the ceiling console frames) follow it, so the game keeps real time up to it. `SAVAGEWIND_FPS_CEILING=<n>` (60..4000). Ctrl+F8 (`menu.mm capture_start`): `sampler_request(15 s, 1 ms)`, a notice while it records and when `build/samples.txt` is written.
- 0.3.18-pc.1, builds for one CPU (`make TUNE=<cpu> EDITION=<name>`, the workflow's `tune` / `edition`, a pre-release): the game code at `-O2 -fwrapv` with the vectorizers for `-march=<cpu>` (its id changes: built again once), WSword itself for it, the version and zip named `<version>-<edition>`; and the fast cores (`plat_cpu_placement`): on a hybrid CPU (EfficiencyClass), one logical processor per performance core where there are 6 or more - on by default in a TUNE build (`WSWORD_FAST_CORES_DEFAULT`), `SAVAGEWIND_FAST_CORES=1/0` anywhere. The first: TUNE=alderlake, EDITION=i7-12700KF.
- Testing: `SAVAGEWIND_RTS_VIEW=1` (the rays alone), `SAVAGEWIND_RTS_CONE=<tan>` (the sun's disc, 0.012), `SAVAGEWIND_RTS_BIAS=<m>,<per m>` (0.03, 0.0025). The ray tracing report (Ctrl+F9) adds the capture's numbers (`rts_report`) and the rays' result (`build/rt-report/rts_rays.png`).
- `exec.c`'s post pass pipeline cache holds 48 (it held 16, fewer than the post shaders and formats in use).
